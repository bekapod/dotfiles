# Herdr

Herdr starts independent Pi agents in terminal panes.

- To start one from the current Pi session, use `/herdr <prompt>`. It creates a right-hand pane in the current repository and starts a fresh `pi --no-session` agent there.
- Give the new agent one clear, bounded task and enough context to begin. It does not share this session's conversation.
- `/gondolin-handoff <branch> <plan-file> [peer-repo-path ...] [--image standard|gbdk] [--model provider/model]` creates a task workspace at `~/agent-clones/<repo>/<branch>`. It clones the current repository and each optional peer repository into sibling directories, creates the branch in each clone, copies the explicit approved plan into the workspace, and starts an isolated Pi agent in a Herdr pane. `standard` is the default image. `gbdk` mounts the read-only GBDK toolchain and includes its build and test environment. Omit `--model` to use `openai-codex/gpt-5.6-luna`. Both have no network, project-loaded extensions, prompts, or repository instruction files. It explicitly loads the user's global `~/.agents/skills`, including TDD and verification workflows. Repositories with duplicate directory names need separate handoffs.
- `/gondolin-plan <branch> [peer-repo-path ...] [--plan path]` asks the current agent to investigate and save a complete plan at `plans/<branch>.md` by default. It requires relevant `principle-*` skills and a plan with no unresolved questions or decisions. It then opens a gated Plannotator review. Annotations return to the agent for revision and another review. Approval prints the equivalent `/gondolin-handoff ...` command but does not start a worker. `/gondolin-review <branch> [repo]` opens a task repository clone in Plannotator from the host. `/gondolin-push <branch> [repo]` pushes that repository's task branch. `/gondolin-pr <branch> [repo]` pushes it and runs `gh pr create --fill`. When the repository has a PR template, it passes that file as `--body-file`, so the template body takes precedence over generated commit text. In a multi-repository task, `repo` is required and must be a sibling clone directory name. The command lists the available names if omitted. This prevents reviewing, pushing, or opening a PR against the wrong repository. `/gondolin-report <branch>` displays the worker's shared verification report. `/gondolin-list` lists every task workspace for the current repository with its last-modified date, active state, and cloned repositories. `/gondolin-clean [--older-than days]` lists workspaces older than 14 days by default, marking active Herdr panes. It never deletes in list mode. `/gondolin-clean --delete <branch>` removes one inactive task workspace and refuses if its pane is active. `/gondolin-resume <branch> [--image standard|gbdk] [--model provider/model]` starts a fresh worker in an existing task workspace without recloning it.
- Handoff workers commit after successful checks using small atomic commits, keeping each code change together with its tests. They write `.gondolin-handoff-report.md` in the task workspace root with commits, changed files, verification commands/results, and limitations. Herdr work is asynchronous. Read the pane output and verify changes locally. Do not rely on the worker's self-report.
- Use `gh stack` through the GitHub CLI when the work belongs in a PR stack.
